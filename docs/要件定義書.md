# FitLog 要件定義書

## 1. プロジェクト概要

### 1-1. 目的

筋トレ・運動記録を SNS 形式で共有し、トレーニング仲間と励まし合えるプラットフォームを提供する。
ITスクール課題として、RAISETIMELINE（Java/Spring Boot）で習得したSNS機能とレイヤードアーキテクチャを、
TypeScript フルスタック（React + NestJS）で再実装する。

### 1-2. 対象ユーザー

- ITスクール受講生、個人トレーニーなど複数ユーザーが利用
- PC・スマートフォンのブラウザから利用

### 1-3. 想定規模

- 同時接続: 数十人程度（スクール課題規模）
- データ量: 数百〜数千投稿

|---|------|------|

## 3. 非機能要件

### 3-1. 認証・セキュリティ

- JWT AccessToken 有効期限: 15 分
- JWT RefreshToken 有効期限: 7 日
- RefreshToken は DB に SHA-256 ハッシュ値のみ保存（生トークン保存不可）
- RefreshToken はセッション（端末）単位で管理し、`session_id` で個別失効可能
- RefreshToken はトークンローテーション方式（使用時に旧トークン無効化 + `replaced_by_token_id` でリプレイ検知）
- RefreshToken Cookie 設定: `HttpOnly`, `Secure`, `SameSite=Strict`, `Path=/api/auth`
- `/api/auth/refresh` は Origin/Referer を検証
- login/refresh はレート制限を適用（IP + アカウント識別子）
- 期限切れ/失効済みトークンは定期ジョブで削除（保持期間を定義）
- パスワードは bcrypt（saltRounds=12）でハッシュ化
- SQL インジェクション対策: TypeORM パラメータバインディング使用
- CORS: フロントエンドのオリジンのみ許可

### 3-2. ストレージ

- 画像は S3 object key のみ DB 保存（URL は DB 保存しない）
- S3 バケットはパブリックアクセスブロック有効、CloudFront OAC でアクセス
- 画像 key には UUID を含めて一意性を保証（同一 key での上書き不可）
- key パス規則: `images/posts/{postId}/{uuid}.{ext}` / `images/avatars/{userId}/{uuid}.{ext}`

### 3-3. パフォーマンス

- タイムライン取得: N+1 問題を TypeORM `QueryBuilder` または `relations` で解消
- DB インデックス: `workout_posts.user_id`, `workout_posts.trained_on`, `likes.workout_post_id`, `comments.workout_post_id`
- CloudFront キャッシュ: `/assets/*` は長期キャッシュ（コンテンツハッシュ）、`index.html` は TTL=0

### 3-4. 可観測性

- NestJS Logger による JSON 形式ログ（timestamp, level, context, message）
- 全 API リクエストのリクエストログ（method, path, status, latency）
- 認証失敗ログ（401 時、ユーザー特定情報なし）
- 認証監査ログ（ログイン成功/失敗、トークン再発行、個別端末失効、全端末失効）
- ログ出力時は token/cookie/password など機微情報をマスキング
- 本番: CloudWatch Logs へ転送

## 4. スコープ外

- プッシュ通知
- DM（ダイレクトメッセージ）
- ハッシュタグ機能
- トレーニング動画アップロード
- 外部認証（Google/Twitter ログイン）
- 管理画面
- 課金・決済機能
- モバイルアプリ（Web のみ）
