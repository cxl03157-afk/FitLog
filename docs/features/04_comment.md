# 機能定義書：コメント機能

## 1. 業務フロー

### 1-1. コメント投稿フロー
```
投稿詳細画面（/workout-posts/:id）を表示
    │
コメント入力フォームにテキストを入力（280 文字以内）
    │
「送信」ボタンをクリック
    │
    ├── バリデーションエラー（空・280 文字超） → エラーメッセージ表示
    │
    └── バリデーション成功
            │
        POST /api/workout-posts/:id/comments を実行
            │
        コメント一覧の末尾にコメントを追加（楽観的更新）
            │
        入力フォームをクリア
```

### 1-2. コメント削除フロー
```
自分のコメントの「削除」アイコンをクリック
    │
確認なしで即時削除（または確認ダイアログを表示）
    │
DELETE /api/comments/:id を実行
    │
コメント一覧から該当コメントを削除
```

## 2. ユースケース

### UC-13: コメント投稿

| 項目 | 内容 |
|---|---|
| UC-ID | UC-13 |
| ユースケース名 | コメント投稿 |
| アクター | 認証済みユーザー |
| 事前条件 | ログイン済み、投稿詳細画面を表示中 |
| 事後条件 | comments レコードが追加され、コメント一覧に表示される |

---

### UC-14: コメント削除

| 項目 | 内容 |
|---|---|
| UC-ID | UC-14 |
| ユースケース名 | コメント削除 |
| アクター | 認証済みユーザー（自分のコメントのみ） |
| 事前条件 | ログイン済み、自分が投稿したコメントを表示中 |
| 事後条件 | comments レコードが削除される |

**代替フロー（権限エラー）:**
- 他ユーザーのコメント ID を直接指定した場合 → 403 Forbidden を返す

---

## 3. 機能要件

- [ ] コメント内容は 1〜280 文字（空コメント不可）
- [ ] コメントは投稿詳細画面にのみ表示（タイムラインには件数のみ表示）
- [ ] タイムラインの投稿カードにはコメント数を表示すること
- [ ] 自分のコメントには「削除」アイコンを表示し、他ユーザーのコメントには表示しないこと
- [ ] 投稿削除時にそのコメントも CASCADE 削除されること

---

## 4. API 設計

| メソッド | エンドポイント | 説明 | 認証 |
|---|---|---|---|
| GET | `/api/workout-posts/:id/comments` | コメント一覧取得 | 必要 |
| POST | `/api/workout-posts/:id/comments` | コメント追加 | 必要 |
| DELETE | `/api/comments/:id` | コメント削除（自分のみ） | 必要 |
