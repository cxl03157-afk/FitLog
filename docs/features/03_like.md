# 機能定義書：ナイス！（いいね）機能

## 1. 業務フロー

### 1-1. ナイス！追加フロー
```
タイムラインまたは投稿詳細画面でナイス！ボタンをクリック
    │
POST /api/workout-posts/:id/likes を実行
    │
    ├── 既にナイス済み → 409 Conflict を返す（DB の UNIQUE 制約で防止）
    │
    └── 成功
            │
        DB に likes レコードを追加
            │
        ボタンの状態を「ナイス済み」に更新（色変更）
            │
        ナイス数を +1 して表示
            │
        ナイスアニメーション（「ナイス！」モーション）を表示
```

### 1-2. ナイス！解除フロー
```
ナイス済みの投稿でナイス！ボタンを再クリック
    │
DELETE /api/workout-posts/:id/likes を実行
    │
    └── 成功
            │
        DB の likes レコードを削除
            │
        ボタンの状態を「未ナイス」に更新
            │
        ナイス数を -1 して表示
```

---

## 2. ユースケース

### UC-11: ナイス！追加

| 項目 | 内容 |
|---|---|
| UC-ID | UC-11 |
| ユースケース名 | ナイス！追加 |
| アクター | 認証済みユーザー |
| 事前条件 | ログイン済み、投稿を表示中 |
| 事後条件 | likes レコードが追加され、ナイス数が増加する |

**代替フロー:**
- 自分の投稿に対してもナイス可能（制限なし）
- 二重ナイスは DB の UNIQUE 制約 `(workout_post_id, user_id)` で防止

---

### UC-12: ナイス！解除

| 項目 | 内容 |
|---|---|
| UC-ID | UC-12 |
| ユースケース名 | ナイス！解除 |
| アクター | 認証済みユーザー（自分がナイスした投稿のみ） |
| 事前条件 | ログイン済み、自分がナイスした投稿を表示中 |
| 事後条件 | likes レコードが削除され、ナイス数が減少する |

---

## 3. 機能要件

- [ ] 同一ユーザーが同一投稿に二重ナイスできないこと（DB UNIQUE 制約 + 409 レスポンス）
- [ ] ナイス数はリアルタイムでフロントエンドに反映すること
- [ ] ナイス追加時はアニメーション（「ナイス！」テキストのフェードアウト等）を表示すること
- [ ] 投稿一覧（タイムライン）では、自分がナイス済みかどうかをボタン状態で表示すること
- [ ] 投稿削除時にそのナイスレコードも CASCADE 削除されること

---

## 4. API 設計

| メソッド | エンドポイント | 説明 | 認証 |
|---|---|---|---|
| POST | `/api/workout-posts/:id/likes` | ナイス！追加 | 必要 |
| DELETE | `/api/workout-posts/:id/likes` | ナイス！解除 | 必要 |
| GET | `/api/workout-posts/:id/likes/count` | ナイス数取得 | 必要 |
